# 古籍 AI 译文

古籍检索完成后，打开任一本书的“译文”页签，使用独立的“AI 译文”区域。无需先生成八字解读。

## 使用

1. 本书返回多篇原文时，先选择“要翻译的原文”；页面显示篇名、原文位置和字符数，并可展开核对待译文本。
2. 在“翻译模型设置”选择智谱或 DeepSeek 及其模型；也可填写自定义模型 ID 和上下文窗口。复用对应平台的会话、本地环境或 secrets 密钥，也可直接在本页密码框填写。
3. 点击“生成 AI 译文”。仅这次点击会发送所选文章，不附带出生资料、命盘、其他书籍或之前报告。切换页签、文章或模型不自动发送请求。
4. 生成后可直接阅读、查看模型列出的待核词句，或下载本篇译文。已有完整缓存时，阅读及下载不需要密钥；“重新生成”按钮会按当前选择重新调用模型。

界面中的模型列表沿用 AI 解读配置。翻译默认不启用可选思考；必须思考的模型仍按其要求启用，并沿用现有请求层的参数及错误处理。按量计费模型的实际用量以平台返回为准，不自动切换模型，也不自动重试。

## 原文对应与长文

- 翻译范围是本次检索返回的完整 `document`，不以全文摘要代替逐段翻译。
- 按原有段落处理，过长段落优先在句号、问号、叹号、分号或换行处切分；极长无标点句才按长度拆分。每段片都有稳定编号，返回时校验数量、编号、顺序及非空译文，拒收明显过短的长段摘要。
- 每批约不超过 1600 个原文字符。发送任何批次之前，使用现有上下文预算机制检查所有待发批次；窗口不足会直接提示，不截断原文。
- 提示词要求保留干支、术语、命例、条件、否定、例外及正文/注文标签；特别提醒食神生财的方向和“官煞俱无”的否定含义。疑义要求列入待核事项。
- 这些是结构及覆盖检查，不是对翻译语义正确性的认证；页面始终标明“AI 辅助译文，未经人工校订”。

## 本地保存

缓存位于项目 D 盘的 `.cache/translations/`，由现有 `.gitignore` 排除，不包含 API Key。

完整译文绑定书名、篇名、来源 ID、完整原文、翻译协议版本及分段长度的哈希。原文或协议变化不会误用旧译文。完整缓存保留生成平台、模型、时间和接口返回的成功请求用量；改变模型不隐藏已保存译文，阅读区显示实际生成模型。

每个成功且校验通过的批次先写入进度文件。发生限流、超时或格式错误时保留此前成功批次，同一篇、同一平台和模型可继续生成。完整结果只在全部片段通过后写入，重新生成失败不会覆盖旧的完整译文。切换平台或模型会使用各自的进度。

译文只用于辅助阅读，不替换古籍原文，也不加入既有原文索引或作为原文引用。
