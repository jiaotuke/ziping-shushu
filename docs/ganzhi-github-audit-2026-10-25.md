## 应处理的缺口

1. **天干生克：优先补齐。** 本地`CONTROLS`目前只参与间隔阻合线索，不会为全部相关天干生成“谁生谁、谁克谁”的独立关系。因此现有模型要求逐条解释的清单并不覆盖所有生克；模型可从四柱自行推演，但程序不能保证逐条核验。参考保留施受方，不复制外部固定吉凶或权重。
2. **刑的方向：优先完善。** 本地`frozenset`保留配对、丢失方向。例如只能给出寅申涉及刑，不能从该记录直接读出申刑寅。应在保留柱位的同时增加施刑方、受刑方；组内两支是否足以论刑、如何定作用另列条件，不把反向作用擅自视为相同。
3. **半会/拱会：扩展候选。** 当前只记录完整三会，不单列两支的半会或两端的拱会。外部项目有此类记录。若纳入，应标记未齐、所缺支和采用口径，不按完整三会算力量。
4. **暗合：扩展候选。** 当前没有暗合关系事件；外部项目有寅丑、卯申、午亥等取法。应先核对原文、藏干参与方式和流派，再决定配置，不能直接把暗合等同六合。
5. **同柱生克：另一个覆盖范围。** 本地关系事件枚举不同柱位，不专门输出盖头、截脚等同柱分类。可考虑独立列事实，不把地支主气简化成该支全部藏干，不直接赋固定吉凶分。

## 不应据此改错的差异

- 午未：bazi-engine取火，china-testing取土；本地不预定化神，属于明确保留分歧，不能判为漏填错误。
- 半合：部分仓库把同一组三合任意两支统称半合；本地把含中神半合和两端拱合分开，与参照中的另一种明确口径一致，不应统一改成“缺一就是半合”。
- 破：china-testing的`zhi_atts`包含六组，而同文件`zhi_poes`注释掉寅亥、巳申两组。外部仓库自身存在表间差异，不能以某一处实现作为唯一标准。
- 合化：本地只输出候选五行、支持/阻碍线索和待核，不判定必然成化。对照开源代码不能替代古籍校核，也不能证明模型对旺衰、喜忌、合绊或现实事件解释正确。
