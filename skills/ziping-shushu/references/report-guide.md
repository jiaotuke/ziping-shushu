# 白话基础报告

先回答用户关心的问题，再给依据。默认按本项目已有的三个方向组织：事业学业、财富资源、感情合作；用户只问其中一项时聚焦该项。不要额外新增健康、疾病、寿命或心境章节。

建议内容：

- 输入及口径：历法、四柱、是否做真太阳时修正、日期是否已确定。
- 核心观察：用简明白话说明传统命理框架下的倾向，避免灾祸或具体事件的确定性断言。
- 三个方向的解读：先给结果，再给适用条件和现实中可观察的线索；不把传统推演当作科学预测或财务决策依据。
- 需要核对的信息：候选日期、出生时间误差、检索缺失、不同书籍口径分歧等。
- 推导依据：支持折叠的 Markdown 环境可用 `<details><summary>查看推导依据</summary>...</details>`；否则放在报告末尾。

依据部分逐项列出“计算事实 → 原文证据 → 本次解释”，引用格式可为：

`《书名》· 篇章，原文第X—Y行（source_id）`

引用文字必须逐字来自工具返回的原文。摘录和翻译分开，现代解释不伪装成原文。原文底本和评注可能混排，不替未标清的文字臆造作者。

命中合、冲、刑、害不等于具体事件发生，也不等于成局成化；月令不被大运流年替换。不得为了给出确定答案改写程序返回的四柱或十神。

普通请求默认提供基础解读与可选大运计算摘要，不自动评分或生成K线。用户明确要求十年大运深入分析、指定范围的大运评分或子平K线时，按 `luck-workflow.md` 执行原局基线、逐运及逐年分析、代码评分和离线交互报告。不得用基础报告冒充完整流程，也不得把“分析十年”自动扩大成六步六十年。

出生信息仅用于用户本次请求。没有用户要求时不将报告或原始资料写入文件，不读写真实账本，不修改代理密码，也不主动连接网站服务器。
