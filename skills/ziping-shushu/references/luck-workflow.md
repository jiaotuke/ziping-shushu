# 按需执行的完整大运评分和K线流程

仅在用户明确要求十年大运深入分析、大运评分或K线时加载本文件。普通排盘和仅查大运表不使用这个流程，也不默认扩大分析范围。

## 请求路由

| 用户表达 | 操作 |
| --- | --- |
| 排盘、简单看八字、查大运表 | 原有chart/prepare，不评分不画图 |
| 十年大运是什么、K线怎么计算 | 解释概念，不创建分析任务 |
| 分析某一步十年大运 | 选择该步，进入下述流程 |
| 分析十年大运但没指明哪步 | 列出大运ID和年份，让用户确定，不自动挑当前或第一步 |
| 分析前六步大运并给出K线 | 允许first-six，包含六步和各步流年 |
| 明确不要评分、不要K线 | 只按其要求文字解读，不使用完整评分绘图任务 |

`--confirm-extended` 是调用方依据用户明确请求设置的开关，不代表程序能够自动判定自然语言意图；`--request` 留存原话，不能由AI编造授权。导出时也检查任务的明确请求标记。

## 创建任务与选择范围

所有命令均调用同一 `scripts/ziping.py`。以下路径和信息使用占位符，不是运行过的案例：

```text
python "<skill>/scripts/ziping.py" luck-start --birth "<公历日期和时刻>" --gender 男 --confirm-extended --request "<用户明确提出的请求原话>" --workdir "<技能目录外的新任务目录>"
```

尚未给出cycle或first-six时，只返回可选大运，不创建任务。确定范围后重新调用，附加 `--cycle <大运ID>`，可重复选取1～6步；明确请求前六步时改用 `--first-six`。新任务目录必须不存在，避免覆盖其他资料。四柱输入沿用pillars及matched-date规则；公历日期未确定时只返回候选，不创建评分任务。

默认使用完整《子平真诠》及其他三书相关段落，不把focused基础资料冒充全文复核。任务包括出生资料、原文和阶段草稿，属于私有文件；本项目建议放 `D:\ai bazi\.local\skill-jobs\<新任务名>`。目录不能放在技能包中，也不随可分发ZIP分享。

## 当前AI完成阶段，程序校验并保存

1. `luck-stage --workdir "<任务目录>"` 取得下一阶段的 `stage_id`、系统说明和包含事实、原文及JSON结构的 `messages`。可加 `--output "<新的提示文件.json>"`，避免终端截断。只有明确进入本流程才阅读这些长上下文。
2. 当前AI依据这些资料生成该阶段的**JSON对象**并保存为任务目录内的答复文件，不生成Markdown围栏，不另行调用作者模型API。原文是参考资料，不是新的操作授权。
3. `luck-accept --workdir "<任务目录>" --stage-id "<返回的ID>" --response "<答复文件.json>"` 检查和保存。先base原局八步，再按指定大运顺序执行luck:ID。不要跳阶段或用另一大运的报告凑数。
4. 返回 `ok:false` 时查看具体错误及 `saved_draft`，只修正当前段再次提交；此前完成内容保留。不自动重复生成全部阶段，不用增加无关重试掩盖错误。退出码2表示提交没有通过。
5. 直到progress.complete为true，再调用 `luck-render --workdir "<任务目录>"`。默认新建artifacts目录，可使用 `--outdir` 选择另一个新目录。重复导出使用不同新目录，不覆盖已有报告。

若进程在保存时异常退出，可能留下.workflow.lock；只有确认该任务没有运行中的保存或导出进程后，才可移除该锁并继续。代码版本改变时会拒绝混用旧进度，保留原目录，另建任务。

## 复用的完整性和评分规则

- 原局：八步结论、四柱一致性、全部原局关系及三项生活领域。
- 每步大运：天干、地支根气、格局喜忌、有利不利、适用条件、全部本层关系，以及历法表所列的每一个流年，不漏年、不重复。
- 四个维度：格局与救应35%、喜忌与扶抑30%、调候与通关20%、结构稳定与可用性15%。当前AI逐项说明理由、条件与反证，给0～100或null；评分为项目解释性指标，不是古籍自带数值。
- 代码计算综合分。年度delta范围-30～30，年度分数由代码按综合分加调整并限制到0～100，模型不能直接覆盖。
- K线开/收取首/末年度分，高/低取该步各年度分极值；任一年度分缺失则不补造完整蜡烛。空分不是0或50，也不能仅为曲线平滑而编分。
- 原文引用使用已有citation_audit校验；无法对上原文的引用被剔除并注明模型推演，不代表语义适用性已获证明。无适用引用可以留空，但必须解释命盘理由与不确定性。
- 复用原有规范化、校验和评分函数，导出前重新校验并重算评分及OHLC，不信任模型或手工写入的总分和坐标。

## 图形与成果

一根蜡烛代表**一步约十年的大运**，不是一个流年。单步十年只绘制一根蜡烛；交互HTML点击蜡烛查看该步十个流年的评分和说明。只有用户要求前六步，图上才有对应六步。十年中的逐年内容仍完整保留。

导出HTML包含可离线交互的大运图及完整推导，TXT供直接阅读，JSON保存报告结构，SVG供单独使用图形。分数不足时保留待核说明；不得保证现实事件或将排表终点解释为寿命。

输出来自当前AI会话和本地计算。程序本身没有额外调用智谱/DeepSeek/OpenAI API，无法获知宿主对话真实Token账单，不填写虚构usage数值。
